# Cloth 봉제선 길이 처리와 바디 핀 병렬 구현 계획

작성: 2026-10-17. 승인: REQ-026. 실행 대화: `01a145a8-6422-7723-a4ce-4509175c3593`의 Astra / Extra High. 시작점: 최소 Cloth 실험 커밋 `47f5dc7`.

## 목표와 실행 방식

기존 Cloth 실험 대화에서 두 기능을 병렬 에이전트로 구현한다. A는 같은 길이·다른 길이의 봉제선 연결, B는 옷을 몸에 의도적으로 붙이는 강제 핀을 담당한다. 새 사용자 대화를 만들지 않는다. 구현 대화의 조정자는 먼저 최소 공통 데이터 계약을 정하고 파일 소유권을 배정한 뒤 두 에이전트를 병렬 실행한다. 조정자가 공통 파일 통합·빌드·최종 검증·커밋을 순차 담당한다.

## 독립 경계와 파일 소유권

쓰기 범위는 기존 `PluginDev/GarmentFitClothProbeHost/`, `Tools/GarmentFitClothProbe/`, `Docs/Implementation/GarmentFitClothProbe/`다. 메인 GarmentFitLab과 이전 LaceGarment의 코드·애셋·레벨·WBP·기록은 수정하지 않는다. 제품 통합도 이번 범위가 아니다.

| 담당 | 전용 파일 영역 제안 | 범위 |
| --- | --- | --- |
| 에이전트 A | 실험 플러그인의 `Private/Sewing/`, `Private/Tests/Sewing/`, `Content/Sewing/`, 전용 Sewing 결과 문서 | 봉제 경계 길이·방향·재샘플링·연결 정책과 테스트 |
| 에이전트 B | `Private/BodyPins/`, `Private/Tests/BodyPins/`, `Content/BodyPins/`, 전용 BodyPins 결과 문서 | 마네킹 사본·천과 몸의 핀 대응·핀 해제와 테스트 |
| 실험 대화 조정자 | 기존 `Probe.h/.cpp`, 입력·실행 연결, Build.cs, 공용 실행 도구, STATUS/REPRODUCTION | 공통 계약 확정·통합·실행·최종 기록·커밋 |

에이전트끼리 공통 파일을 동시에 수정하지 않는다. 구체적인 클래스/API는 현재 UE 코드와 기능 요구를 확인한 뒤 조정자가 정하며, 확정한 공통 계약은 두 에이전트에게 동일하게 전달한다. 에이전트는 Git 커밋과 공용 빌드를 별도로 실행하지 않는다.

## A — 같은 길이와 다른 길이의 봉제선

- 조각의 경계 구간과 방향을 지정해 연결한다. 정점 수가 같다는 이유로 같은 길이라고 판단하지 않고 2D 원본 경계의 호 길이를 비교한다.
- 같은 길이에서 정점 수/샘플 간격이 달라도 대응점을 구성한다. 정방향·역방향과 명시적 뒤집기 옵션을 검사한다.
- 다른 길이도 명시적인 정책으로 연결할 수 있게 한다. 원본 길이, 차이, 비율을 표시하고 원본을 몰래 스케일하거나 동일 길이로 덮어쓰지 않는다.
- 최소 지원안은 양 경계의 정규화된 호 길이로 대응시키는 비율 봉제다. 두 패널의 원본 길이는 보존하며 실제 늘어남·줄어듦·주름 및 수렴은 물리 결과로 측정한다. 이 정책을 실제로 검증할 수 없으면 지원한다고 표시하지 않고 제한과 원인을 보고한다.
- 동일 길이만 허용하는 검증 모드도 구분한다. 길이 차이를 거부한 결과만으로 다른 길이 봉제 기능 완료를 주장하지 않는다. 범용 재봉 이즈/주름 품질까지 자동 보장하지 않는다.
- 동일 길이, 다른 샘플 수, 방향 반대, 길이 비 1:1.5와 1.5:1, 0 길이·범위 밖 경계·겹치는/중복 대응·비유한 값 등 입력 검증을 포함한다. 동일/다른 길이의 실제 시뮬레이션과 원본 보존, 초기화, 저장/재열기를 확인한다.

## B — 몸에 붙이는 강제 핀

- 천의 지정 정점 또는 지정 영역을 몸의 지정 목표점에 붙이고 유지하는 명시적 hard pin을 구현한다. 기존 월드 좌표 고정과 몸에 대한 부착을 구분한다.
- 핀 데이터에는 천 쪽 대상, 바디 쪽 대상, 기준 공간과 필요한 표면 오프셋을 둔다. 처음에는 API/검증 입력으로 지정할 수 있으면 충분하며 별도 클릭 편집기·새 UI는 추가하지 않는다.
- 생성·활성/비활성·해제·초기화·저장/재열기를 지원한다. 바디 이동/회전 후 목표점을 따라가는지, 해제 후 자유 시뮬레이션이 복구되는지 확인한다. 골격 변형 추종을 지원하는 경우에만 해당 포즈 테스트와 함께 지원 범위를 보고한다.
- 잘못된 바디/정점/목표, 서로 상충하는 핀, 중복 핀, 봉제 뒤 용접 정점으로의 대응을 검증한다. 충돌체 안쪽 목표 등 물리적으로 상충하는 조건의 거부/처리 기준을 명확히 한다.
- 핀 위치와 강제 고정 상태를 실험 화면에서 식별할 수 있게 한다. 핀 사용 결과와 핀 없는 결과를 비교하고, 강제 부착을 자연스러운 피팅 성공으로 보고하지 않는다.

## 마네킹 독립성

REQ-026은 핀 검증을 위한 마네킹의 읽기·참조·복사를 허용한다. 이전 최소 실험의 캐릭터 사용 제외는 이 후속 범위에 한해서 해제한다. 메인 원본 수정은 허용하지 않는다.

메인은 마네킹을 수정 중이므로 안정된 커밋의 사본을 우선 사용한다. 현재 후보는 `Content/GarmentFitLab/Characters/LunaMk2/SKM_LunaMk2_Mannequin.uasset` 및 관련 골격·재질 또는 대응 FBX다. 실제 의존성을 확인하고 실험 호스트 내부의 고유 패키지 경로로 복제·재매핑하거나 원본 파일 사본에서 임포트한다. 메인 `/Game/` 참조를 런타임 필수 의존으로 남기지 않는다. 원본 경로·기준 커밋 또는 해시·복제 시점을 기록한다. 변경 중인 파일을 불완전하게 복사하지 않는다. 필요한 부분만 고정하고 메인의 체형 보정 작업을 기다리며 추종하거나 재수행하지 않는다.

## 검증과 커밋

기존 최소 실험 회귀, 두 기능 각각의 자동화·시뮬레이션·저장/재열기·화면 확인, 봉제와 핀을 함께 적용한 최소 통합 예제를 확인한다. 봉제 오차·원본 길이 대비 변형, 핀 목표 추종 오차·해제 후 이동, 관통 측정의 범위를 기록한다. 기존과 같이 설치 엔진과 다른 대화 프로세스는 변경하지 않고 UBT mutex를 존중한다.

조정자가 검증 결과와 현재 공유 index를 확인한 뒤 자기 파일만 명시적 경로로 커밋한다. 가능하면 봉제 기능과 핀 기능을 각각 검증 가능한 커밋으로 나누고 필요한 통합 변경을 마지막에 둔다. 중간 커밋은 미완료 상태를 명시한다. 성공한 검사·한계·재현 방법·기능별 커밋 해시를 보고하고 후속 범위로 자동 진행하지 않는다.
