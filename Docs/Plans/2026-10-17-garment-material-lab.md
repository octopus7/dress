# GarmentMaterialLab 재질과 천 물성 반복 실험 계획

작성: 2026-10-17. 승인: REQ-027. 실행: 별도 Astra (`gpt-6-astra`) / xhigh 대화.

## 목표

사용자가 느끼는 얇고 쭈글거리는 천을 개선하기 위해 여러 재질·물성 설정을 반복 비교한다. 목표는 **탄성이 있고 부드러운 주름이 생기는 클레이 반죽 같은 느낌, 어느 정도 두께가 느껴지는 귀여운 게임용 외형, 적은 주름과 자연스러운 여유**다. 지나치게 팽팽하거나 딱딱한 판처럼 만드는 결과는 목표에 맞지 않는다.

사용자의 스타일 설명은 물성·외형의 목표이며 체적 클레이 솔버나 영구 소성 변형 시스템을 새로 만들라는 요구로 확장하지 않는다. 정답인 재질 수치를 사전에 단정하지 않고 기준군·후보군을 같은 조건으로 비교해 사용자에게 보여준다.

## 독립 경계와 기준 버전

- 작업 호스트: `PluginDev/GarmentMaterialLabHost/`, 그 아래 고유 플러그인 `GarmentMaterialLab`.
- 도구: `Tools/GarmentMaterialLab/`. 실행·보관·재현에 필요한 최소 도구만 작성한다.
- 기준 입력은 검증된 최소 Cloth 실험 커밋 `47f5dc7ee3e32ac65e0b9acb55a16a07e9da3e00`의 스냅샷이다. 그 커밋의 필요한 파일만 복사하고 호스트·플러그인·모듈·자동화·패키지 이름과 출력 경로를 독립시킨다. 작업 중인 봉제·핀 코드나 현재 워킹트리 변경을 따라가지 않는다.
- 메인 `Plugins/GarmentFitLab`, 기존 `PluginDev/GarmentFitClothProbeHost`, 이전 `PluginDev/LaceGarmentHost`, 루트 프로젝트/애셋/기록은 수정하지 않는다. 설치 엔진도 읽기 전용이다. 다른 대화에 작업 지시를 보내지 않는다.
- 자기 호스트의 Binaries/Intermediate/Saved/DerivedDataCache와 플러그인 생성물은 호스트 내부 `.gitignore`로 제외한다. 공유 `.gitignore`를 불필요하게 변경하지 않는다.

## 실행 방식

**에디터 UI, 컴퓨터 유즈, CUA, 화면 좌표 조작을 사용하지 않는다.** 빌드·설정·시뮬레이션·애셋 생성/검사·검증은 전부 커맨드라인과 자동화/commandlet로 실행한다. 시각 비교는 커맨드라인에서 만든 오프스크린 렌더와 이미지 파일 열람으로 수행한다. UI가 없는 실행과 렌더링이 없는 실행을 구분하여 필요한 렌더는 headless/offscreen으로 생성한다. 가능한 플래그는 설치 UE 5.8에서 확인한다.

## 비교 축과 실험 순서

1. 기준 커밋에서 현재 기본 설정을 재현하고 원본 조건·화면·측정값을 보존한다. 기존 스냅샷의 테스트 횟수와 성공 여부를 새 호스트에서 다시 확인한다.
2. 물리적 반응(신장/전단/굽힘·감쇠·질량·마찰), 충돌상 두께, 렌더링상의 두께/표면을 분리해 조사한다. 실제 지원되는 UE 설정과 단위를 소스로 확인한다.
3. 우선 메시·고정점·봉제·카메라·조명·시간 간격·solver 정밀도를 고정하고 소수 물성 축을 비교한다. 얇은 기본군, 탄성 위주, 부드럽고 도톰한 후보 등 초기 비교군을 만든다.
4. 주름을 줄이면서도 처짐·탄성·복원이 남는 후보를 골라 주변 값을 재탐색한다. 단순히 고정점 증가나 과도한 늘림으로 천을 팽팽하게 만든 결과를 개선으로 평가하지 않는다.
5. 렌더 외형의 두께와 부드러운 무광 표면을 별도 비교한다. 시뮬레이션 메시 두께·충돌 여유·렌더 표면 두께를 같은 값으로 취급하지 않는다. 시각 효과만 좋아진 경우 물성 개선과 구분한다.
6. 유력 후보는 같은 조건의 늘어뜨리기·곡면 위 처짐·작은 압축·늘림 후 복원에서 비교한다. 필요한 단순 fixture만 추가하고 캐릭터 제작·옷본 생성·봉제/핀 시스템 개발로 확장하지 않는다.
7. 메시 해상도와 solver 정밀도를 바꾼 제한된 재검사로 수치 불안정/해상도 효과와 재질 효과를 구분한다. 새 프로세스 반복·초기화·애셋 재열기를 확인한다.

주름의 개수·크기·날카로움, 원본 대비 길이 변화, 처짐, 복원 속도·진동, 관통과 계산 비용을 화면과 측정 가능한 지표로 비교한다. 숫자 하나로 미적 만족을 확정하지 않는다. 미지원 측정과 부분 검증을 명시한다.

## 성공과 실패의 보관

중앙 보관 경로는 `Saved/GarmentMaterialLab/Trials/<고유 실행 ID>/`다. 루트 `.gitignore`의 `/Saved/`로 제외됨을 확인했다. 실행 전 `git check-ignore`로 실제 출력 경로를 다시 확인한다.

- 매 실행 **전에** 전체 파라미터·단위, 입력/코드 해시, 기준 커밋과 변경 patch, 사용 엔진·환경, 메시·고정점·충돌·solver 설정, 실행 명령을 기록한다.
- 실행 후 결과 metrics JSON, 로그, 자동화 보고서, 프레임/비교 이미지, 필요 애셋·메시·시뮬레이션 기록, 결과 해석을 같은 실행 ID로 보존한다.
- crash/timeout/빌드 실패/불안정/시각적 탈락도 상태와 이유를 기록하고 부분 산출물을 유지한다. 실패한 설정이나 재현에 필요한 당시 코드 차이를 덮어쓰거나 삭제하지 않는다.
- 성공·실패 모두 누적 인덱스에 기록한다. 결과물은 Git에 추가하거나 `git add -f`로 강제 포함하지 않는다. 후보 프리셋과 실험 코드는 이번 탐색 중 자동 커밋하지 않는다. 최종 선택 이후 보존·커밋 범위는 따로 정한다.
- UE 생성 애셋을 임시 Content 경로에 써야 한다면 이 호스트의 전용 trial 경로만 추가로 ignore하고, 중앙 실행 폴더에 재현 가능한 사본/manifest를 남긴다. 제품 원본 전체를 ignore하지 않는다.
- 정리 스크립트·`git clean`·자동 용량 청소로 실패 결과를 지우지 않는다. 저장 공간이 부족하면 다음 배치를 멈추고 보존 상황을 보고한다.

나중에 사용자가 문서 비교 기록을 요청하면 이 누적 자료에서 추출한다. 현재 단계에서 실패를 버리거나 완성 비교 보고서로 임의 확정하지 않는다.

## 지속 실행과 대화 보고

첫 성공 한 번으로 끝내지 않고 기준군 → 후보 비교 → 유력 영역 재탐색 → 교차 검증을 이어간다. 각 배치가 끝날 때 대화에 실행 ID·바꾼 설정·좋아진 점·나빠진 점·실패와 원인·다음 비교를 남기고 대표 이미지를 보여준다. 긴 배치 중에도 의미 있는 진행 상황을 알린다. 단순 실행 나열보다 사용자가 재질 차이를 판단할 근거를 제공한다.

사용자 피드백은 다음 배치에 반영한다. 후보가 충분히 비교 가능한 수준으로 모이면 2~3개를 제시하되, 사용자 취향 확인 전 최종 재질을 확정하지 않는다. 개선이 정체되면 근거와 다음 선택을 보고하며 같은 실패를 무기한 반복하지 않는다. 미래 예약이나 별도 자동화는 요청하지 않았으므로 만들지 않는다.
