# GarmentFitClothProbe 최소 Cloth 실험 계획

작성: 2026-10-17. 승인: REQ-024. 담당: 별도 Astra (`gpt-6-astra`) / Extra High (`xhigh`) 대화.

## 목표

직접 만든 재단 완료 패널 두 장과 대응 봉제선으로 UE 5.8 기본 Cloth 시뮬레이션 경로가 작동하는지 확인한다. 봉제 연결, 중력 변형, 기본 충돌, 초기화, 저장·재열기를 검증하고 실험 변경만 별도로 커밋한다. GarmentFitLab 단계 2에 필요한 최소 기술 실증이며, 실제 의상·체형 자동 분석·제품 통합 완료가 아니다.

## 독립 경계

기존 메인 대화는 그대로 진행한다. 실험을 이유로 메인 대화에 지시를 보내거나 메인의 파일·진행 단계를 변경하지 않는다.

| 실험에서 쓰기 가능한 경로 | 용도 |
| --- | --- |
| `PluginDev/GarmentFitClothProbeHost/` | 최소 개발 호스트, 그 아래 독자 `GarmentFitClothProbe` 플러그인 및 실험 애셋 |
| `Tools/GarmentFitClothProbe/` | 필요할 때만 추가하는 전용 실행·검증 도구 |
| `Docs/Implementation/GarmentFitClothProbe/` | 실험 결과, 재현 방법, 알려진 한계 |

제품 파일은 위 범위에서만 작성한다. `Plugins/GarmentFitLab/`, 루트 `Source/Content/Config/LaceLoft.uproject`, `Docs/Implementation/GarmentFitLab/`, `PluginDev/LaceGarmentHost/` 및 기존 게임/플러그인 구현 기록은 수정하지 않는다. `AGENTS.md`, 공유 `Docs/REQUESTS.md`, 기존 설계·계획도 실험 대화가 수정·커밋하지 않는다.

실험 호스트는 메인 플러그인 경로를 추가 로드하거나 링크하지 않는다. 프로젝트·플러그인 이름, Source·Content·Binaries·Intermediate·Saved 경로를 독립시킨다. 이 호스트는 개발용 검증 장치이며 배포할 추가 제품을 만드는 작업이 아니다. 메인 테스트 레벨과 WBP는 사용하지 않고, 전용 임시 월드 또는 실험 호스트 내부 미리보기만 사용한다.

## 구현 범위

- 새로 정의한 단순 패널 두 장의 2D 원본, 삼각형, 초기 3D 위치, 대응 봉제 경계를 준비한다. 기존 LaceGarment의 코드·더미·패널·솔버를 복사하지 않는다.
- 초기 봉제 경계가 맞닿도록 배치한다. 떨어진 평면 옷본을 자동으로 몸에 감아 봉제하는 동작은 요구하지 않는다.
- 설치 UE 5.8의 기본 Cloth Asset/Collection/Dataflow/Component 경로를 사용한다. 실제 API는 설치 소스에서 확인한다.
- 고정점은 명시하고, 중력에 의해 움직이는 영역과 구분한다. 먼저 바디 없는 봉제·중력 실험을 확인한 뒤 단순 구 또는 캡슐 충돌 하나를 확인한다.
- 2D 원본, 초기 3D 배치, 시뮬레이션 결과를 구분하여 초기화 후 같은 입력으로 다시 실행할 수 있게 한다.
- 실제 캐릭터, Luna 입력, 체형 분석, 원피스/셔츠 옷본 생성, 스킨 웨이트 범용 보정, 새 UI, 독자 솔버, 배포·cook은 구현하지 않는다.
- 첫 기본 경로가 막히면 원인·실행 근거·다음 제안을 보고한다. 장시간 독자 솔버 개발이나 범용 구조로 확대하지 않는다.

## 검증과 제출물

1. 전용 호스트의 Editor 빌드와 고유 `GarmentFitClothProbe` 자동화를 실행한다. 모든 명령에 실험 `.uproject` 절대 경로와 고유 출력 폴더를 지정한다.
2. 없는 패널/잘못된 대응 인덱스·퇴화 입력의 거부와 유효한 봉제 연결을 확인한다.
3. 고정된 시간 간격으로 10초 실행하여 봉제 연결, 실제 자유 영역 변형, 유한 좌표, 기본 충돌, 불안정 여부를 확인한다. 정점 관통만 측정했다면 면 관통이나 전체 품질까지 검증했다고 주장하지 않는다.
4. 초기화 후 재실행과 Cloth 애셋 저장 후 새 프로세스 재열기를 확인한다. 원본 패널을 시뮬레이션 결과로 덮어쓰지 않는다.
5. 처음/변형 후/초기화 후 화면과 실행 명령·측정값·실패 또는 미검증 항목을 전용 기록에 남긴다. 로그만으로 시각적 품질을 단정하지 않는다.
6. 검증된 실험 파일만 명시적 경로로 커밋하고 커밋 해시·성공한 검증·남은 한계·사용자가 재현할 방법을 보고한 뒤 멈춘다. 미완료를 저장하는 경우 중간 커밋임을 명시한다.

## 공용 자원과 Git

- 설치 엔진은 읽기 전용으로 취급한다. 엔진 수정·업데이트, 공용 캐시 삭제, 다른 대화의 UE/Blender/빌드 프로세스 종료를 하지 않는다.
- UBT의 mutex와 `-WaitMutex`를 존중해 빌드를 순차 실행한다. 별도 호스트의 고유 DLL·애셋·로그만 사용한다. 동시 실행에 자원 충돌이 있으면 실험 실행을 미룬다.
- 저장소의 Git index는 공유된다. 커밋 직전에 상태를 다시 확인하고 자기 파일을 명시적으로 스테이징한다. 일반 `git commit`으로 전체 index를 묶지 않고 경로 제한 커밋을 사용한다. 브랜치 전환·reset/clean·전체 스테이징·다른 작업 변경 포함을 금지한다.
- 다른 Git 동작의 lock이 있으면 기다리고 재확인한다. 상대 lock이나 staged 변경을 지우지 않는다.
- 메인 플러그인으로의 코드·애셋 통합은 이번 범위에 없으며 사용자 검토 후 별도로 결정한다.
