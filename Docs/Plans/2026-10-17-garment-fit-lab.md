# GarmentFitLab 기능별 구현 계획

> 실행 담당: 별도의 Astra (`gpt-6-astra`) / High 구현 대화. 단계별 실행에는 `superpowers:executing-plans`를 사용한다. REQ-022로 단계별 구현·검증·커밋이 승인되었다. 현재는 단계 1만 진행하고, 해당 변경을 커밋해 결과를 보고한 뒤 사용자의 다음 단계 지시를 기다린다.

**Goal:** 제공 캐릭터의 체형에 맞춘 반팔 셔츠·끈 원피스의 재단 완료 옷본과 봉제선을 자동 생성하고, 배치·시뮬레이션 수준을 기능별로 확인한다.

**Architecture:** 새 `Plugins/GarmentFitLab/`에 기능과 UI를 둔다. 프로젝트는 새 테스트 레벨 하나로 플러그인을 사용한다. 기존 게임 기능 및 LaceGarment 구현에 의존하지 않는다.

**Tech Stack:** UE 5.8, C++, 실제 WBP, Chaos Cloth/Cloth Asset/Dataflow.

**Spec:** [GarmentFitLab 설계](../Design/GARMENT_FIT_LAB_DESIGN.md), REQ-021~022.

## 진행 원칙

- 단계 1~7은 전체 순서이며 일괄 구현 목록이 아니다. 매 단계에서 결과를 사용자가 확인한 뒤 다음 작업을 결정한다.
- 기존 구현 대화와 그 작업물은 그대로 둔다. 이 계획의 검증 결과와 진행 기록을 혼합하지 않는다.
- 처음 제공되는 캐릭터 한 개와 고정 포즈부터 지원한다. 원단 자르기·범용 의상 분류·독립 배포·포즈 라이브러리를 추가하지 않는다.
- 화면은 실제 WBP에서 편집하며 C++에서 위젯 트리를 만들지 않는다.
- 코드·애셋을 변경한 단계에서는 UE 5.8 Editor 빌드, 새 `GarmentFitLab` 자동화와 해당 단계에 필요한 애셋 저장/재열기·실행 검증을 한다. 기존 게임 연결에 영향을 준 단계는 `LaceLoft` 자동화도 실행한다.
- 실행하지 않은 검사와 제공되지 않은 메시에서의 동작을 통과로 표시하지 않는다. 품질 미달도 재현 가능한 결과로 제출하고 보완 범위를 조율한다.
- 현재 작업과 빌드가 겹치면 순차 실행하며 다른 대화의 프로세스를 종료하지 않는다. 단계별 검증 후 해당 단계의 변경만 커밋하고 커밋 해시·검증 결과·미완료 항목을 보고한다. 다른 작업의 변경을 포함하거나 공유 저장소에서 브랜치를 전환하거나 전체 스테이징하지 않는다.
- 사용자 캐릭터가 아직 제공되지 않았다면 단계 1의 플러그인·테스트 레벨·입력 지정 기반을 먼저 구현·검증할 수 있다. 이 경우 검증된 기반을 중간 커밋하고 메시 미제공과 실제 캐릭터 표시 미검증을 명시한다. 기존 더미를 대신 사용하거나 단계 1 전체 완료 및 단계 2 착수로 처리하지 않는다.

## 단계 1 — 플러그인과 테스트 레벨에서 제공 메시 표시

**산출물:** 기존 게임 흐름과 분리된 테스트 레벨에서 사용자가 제공한 캐릭터를 볼 수 있다.

**대상:** 플러그인 등록/모듈, `GarmentFitPreviewActor.h/.cpp`, 테스트 레벨, 최소 WBP.

- [ ] 제공 메시의 애셋 종류·단위·앞/위 방향·기준 포즈·골격·몸 표면 분리를 확인하고 첫 지원 입력을 기록한다.
- [ ] 새 플러그인과 테스트 레벨을 만들고 메시를 외부 입력으로 지정해 표시한다. 아직 제공되지 않았다면 메시 표시 완료를 주장하지 않는다.
- [ ] 잘못된/비어 있는 메시 입력을 명확히 표시하고 기존 게임 모듈·기존 플러그인에 참조가 없는지 확인한다.
- [ ] Editor 빌드, `GarmentFitLab.Input` 및 기존 연결 관련 `LaceLoft` 검사, 레벨/WBP 저장·재열기를 확인한다.

**사용자 확인:** 캐릭터의 크기·방향·포즈와 테스트 화면. 이 시점에는 옷본 생성이 없다.

## 단계 2 — 재단 완료 패널의 봉제와 기본 시뮬레이션

**산출물:** 단순한 두 패널에서 봉제 연결·천 변형·초기화가 보이는 최소 실험.

**대상:** `GarmentPatternData.h`, `GarmentClothBuilder.h/.cpp`, 미리보기 액터, `Content/Examples/`.

**입출력:** `FGarmentPanel`은 ID·2D 정점·삼각형·초기 3D 정점을 가진다. `FGarmentSeam`은 대응 패널 ID·경계 정점 쌍을 가진다. `FGarmentPatternSet`을 Cloth 생성기의 입력으로 삼는다. 원본 패널과 시뮬레이션 출력은 분리한다.

- [ ] `GarmentFitLab.Pattern.InvalidSeam`으로 범위 밖 인덱스·없는 패널·퇴화 삼각형 거부를 먼저 확인한다.
- [ ] 새로 만든 두 패널을 대응 경계가 맞닿도록 배치하고 봉제선을 같은 색으로 표시한다. 원단을 자르는 단계는 만들지 않는다.
- [ ] 설치 UE 5.8의 Collection→설정→Cloth Asset→Component 연결을 최소한으로 실행한다. 떨어진 패널 자동 드레이핑을 성공 조건으로 추가하지 않는다.
- [ ] 임시 고정점이 표시된 상태에서 10초 중력 변형과 초기화 후 재실행을 확인한다. 바디 없는 연결을 먼저 확인하고 별도로 제공 바디의 충돌 입력을 확인한다.
- [ ] 빌드·`GarmentFitLab.Pattern`·Cloth 애셋 저장/재열기를 확인하고 연결·관통·불안정 결과를 기록한다.

**사용자 확인:** 봉제한 천이 실제로 움직이는지. 막히면 여기서 원인과 다음 실험만 조율하며 자동 생성이나 자체 솔버로 작업을 확대하지 않는다.

## 단계 3 — 캐릭터 체형 자동 분석 표시

**산출물:** 어깨·가슴·허리·골반·팔의 인식 지점과 치수가 캐릭터 위에 보인다.

**대상:** `GarmentBodyAnalysis.h/.cpp`, 최소 결과 표시.

**입출력:** 제공 메시와 기준 포즈 → `FGarmentBodyProfile`(좌표계, 기준점, 길이/둘레, 각 항목의 분석 성공 여부). 다음 생성기는 이 프로필만 받는다.

- [ ] `GarmentFitLab.Body`에서 단위 변환·좌우 구분·표면 단면 측정과 기준점 누락 시 실패 표시를 검사한다.
- [ ] 제공 메시에서 골격 기준점과 실제 몸 표면을 함께 사용해 필요한 치수를 계산한다. 골격이 없거나 몸 표면이 분리되지 않는 입력은 지원 여부를 먼저 판단한다.
- [ ] 자동 결과와 수동 보정을 구분하여 표시하고, 사용자가 실제 위치·치수를 확인할 수 있게 한다.
- [ ] 빌드·분석 자동화·테스트 레벨 실행으로 같은 입력의 결과가 재현되는지 확인한다.

**사용자 확인:** 체형을 올바르게 읽었는지. 이 단계 결과를 확인하기 전에 두 의상 치수 보정으로 넘어가지 않는다.

## 단계 4 — 끈 원피스 옷본과 봉제선 자동 생성

**산출물:** 체형에 맞는 앞판·뒤판·두 어깨끈과 봉제 대응선이 2D에 표시된다.

**대상:** `StrapDressPattern.h/.cpp`, 패널 표시 뷰.

**입출력:** `FGarmentBodyProfile` + 기장/여유분/끈 폭 → `FGarmentPatternSet`.

- [ ] `GarmentFitLab.Pattern.StrapDress`에서 네 조각, 좌우 옆선, 네 끈 끝의 연결, 열린 상단·밑단, 자기교차 없는 패널을 검사한다.
- [ ] 체형·설정값으로 패널 곡선과 대응 봉제 구간을 생성하고 같은 봉제 쌍에 같은 ID/색을 표시한다.
- [ ] 기장과 여유분 변경 시 관련 옷본만 의도대로 바뀌고 봉제 대응이 유지되는지 확인한다.
- [ ] 빌드·패턴 자동화·2D 표시와 원본 저장/재열기를 확인한다.

**사용자 확인:** 옷본 모양·치수·봉제선의 의미. 자동 생성 완료와 착장 완료를 구분한다.

## 단계 5 — 끈 원피스 배치와 착장 시뮬레이션

**산출물:** 생성한 원피스를 제공 캐릭터에 배치하고 움직임과 형태를 확인할 수 있다.

**대상:** `StrapDressPlacement.h/.cpp`, 단계 2 Cloth 연결과 미리보기.

- [ ] 패널을 몸 주변에 배치하고 끈을 어깨 위로 연결한다. 원본 2D 치수, 초기 위치, 결과 위치를 구분한다.
- [ ] `GarmentFitLab.Placement.StrapDress`에서 봉제 대응 경계·초기 위치의 유효성·초기화 재현과 원본 불변성을 검사한다.
- [ ] 고정 포즈 10초 실행 후 정면·측면·후면에서 끈 위치, 밑단, 관통·늘어남·봉제 벌어짐을 확인한다. 임시 고정점의 효과는 따로 표시한다.
- [ ] 빌드·해당 자동화·생성 Cloth 저장/재열기를 확인하고 현재 품질과 남은 문제를 제출한다.

**사용자 확인:** 원피스 수준이 다음 의상으로 넘어갈 만한지, 원피스를 더 보완할지 결정한다.

## 단계 6 — 반팔 셔츠 옷본과 봉제선 자동 생성

**산출물:** 앞몸판·뒤몸판·좌우 소매와 모든 봉제 대응선이 2D에 표시된다.

**대상:** `ShortSleeveShirtPattern.h/.cpp`, 공통 패널 표시.

**입출력:** `FGarmentBodyProfile` + 몸판 기장/소매 길이/여유분 → `FGarmentPatternSet`.

- [ ] `GarmentFitLab.Pattern.ShortSleeveShirt`에서 네 조각, 어깨·옆선·소매 아래선·소매산 대응, 열린 목·소매 끝·밑단을 검사한다.
- [ ] 어깨·가슴·목·위팔 치수로 기본 옷본을 만들고 소매산과 앞뒤 진동의 구간별 길이·방향·샘플을 맞춘다.
- [ ] 소매 길이 변경과 좌우 대응을 검사하고, 없는 기준점이나 성립하지 않는 치수는 생성 실패로 표시한다.
- [ ] 빌드·패턴 자동화·2D 표시와 원본 저장/재열기를 확인한다.

**사용자 확인:** 반팔 형태와 소매 봉제선이 의도대로 생성되는지. 셔츠 착장은 다음 단계이다.

## 단계 7 — 반팔 셔츠 배치와 착장 시뮬레이션

**산출물:** 제공 캐릭터가 생성된 반팔 셔츠를 입은 상태에서 시뮬레이션을 확인할 수 있다.

**대상:** `ShortSleeveShirtPlacement.h/.cpp`, 공통 Cloth 연결과 미리보기.

- [ ] 몸통과 팔 주변에 패널을 배치하고 소매 봉제 경계를 맞춘다. 겨드랑이 충돌과 좌우 소매 방향을 우선 확인한다.
- [ ] `GarmentFitLab.Placement.ShortSleeveShirt`에서 원본 불변성·유효한 배치·초기화 재현을 검사한다.
- [ ] 고정 포즈 10초 실행 후 목·어깨·겨드랑이·소매·밑단의 형태와 관통·늘어남·봉제 벌어짐을 기록한다.
- [ ] 빌드·해당 자동화·저장/재열기를 확인한다. 원피스도 같은 공통 경로가 바뀐 경우에만 필요한 회귀를 실행한다.

**사용자 확인:** 두 의상 각각의 자동 생성 수준과 착장 수준. 이 결과를 바탕으로 후속 기능을 별도로 정한다.

## 검토 집중 항목

| 실패 가능성 | 확인 단계 |
| --- | --- |
| 단위·좌우·기준 포즈 오류로 체형이 잘못 읽힘 | 1, 3 |
| 봉제 방향 반대, 없는 경계, 목·밑단을 잘못 봉합 | 2, 4, 6 |
| 2D 원본을 3D 결과로 덮어써 치수나 초기화가 달라짐 | 2, 5, 7 |
| 충돌체가 겨드랑이 공간을 막거나 실제 몸 표면과 다름 | 2, 5, 7 |
| 기본 패널·자동화 성공을 실제 두 의상의 품질 완료로 혼동 | 모든 사용자 확인 단계 |

첫 구현 착수 전에 필요한 입력은 사용자가 제공할 캐릭터 메시다. 제공 후 단계 1만 구체적인 입력 경로와 실행 명령으로 확정한다. 후속 단계의 세부 API는 앞 단계에서 확인한 설치 엔진 경로를 기준으로 정하고, 전체 구현을 한 번에 지시하지 않는다.
