# GarmentFitLab 체형 기반 옷본 생성 실험 설계

작성: 2026-10-17. 상태: REQ-022에 따라 별도 Astra / High 대화에서 단계별 구현·검증·커밋 진행. 현재 착수 범위는 단계 1이며 후속 단계는 결과 확인 후 조율한다. 근거: REQ-021~022.

## 목적과 확정된 요구

사용자가 제공하는 캐릭터 메시의 체형을 자동 분석하여 **소매가 있는 반팔 셔츠**와 **소매 없이 어깨끈으로 걸치는 원피스**의 옷본·봉제선을 각각 생성한다. 생성된 옷본은 이미 재단이 끝난 조각이다. 몸 주변 배치와 시뮬레이션 결과를 보면서 기능별 구현 수준을 판단한다.

자동인식의 입력은 캐릭터 메시다. 의상 메시를 받아 옷 종류를 분류하는 기능이 아니다. 사용자는 2026-10-17에 이 해석을 확인했다. 두 의상은 정해진 기본 형식이며, 체형에 맞춰 치수와 곡선을 계산한다.

기존 LaceLoft 의상 제작 기능 및 별도로 진행 중인 LaceGarment 구현과 완전히 독립적으로 처음부터 만든다. 기존 구현의 코드·의상·더미·문서 모델·파일 계약·완료 조건을 복사하거나 의존하지 않는다. 진행 중인 구현은 변경하거나 중단하지 않는다.

## 이번 제안의 경계

- 처음 제공되는 캐릭터 메시 한 개와 고정된 기준 포즈를 첫 지원 대상으로 삼는다. 모든 체형·골격·포즈의 범용 지원은 약속하지 않는다.
- 첫 의상 형식은 칼라·단추·주머니 없는 기본 반팔 셔츠와 단순한 끈 원피스를 제안한다. 앞여밈이나 장식의 추가 여부는 별도 조율한다.
- 원단 펼치기, 원단 위 배치, 재단선 따라 자르기, 재단 진행률, 수동 봉제 게임 과정은 없다.
- 독립 파일 포맷, ZIP 배포, 외부 프로젝트 인수, cook, 게임 패키징, 전용 범용 옷본 편집기, 애니메이션·포즈 라이브러리는 이번 목표에 넣지 않는다.
- UE 5.8 안에서 실행하며 Blender·외부 저작툴·외부 서버를 필수 의존성으로 두지 않는다. 독자적인 천 물리 솔버 개발은 계획에 포함하지 않는다.
- 각 단계가 끝나면 사용자가 결과를 확인하고 보완 또는 다음 단계를 결정한다. 이 문서는 전 단계 일괄 실행 승인이 아니다.

## 플러그인과 프로젝트의 역할

가칭 플러그인은 `Plugins/GarmentFitLab/`에 새로 만든다. 생성·분석·배치 기능은 `GarmentFitLabEditor`, 데이터·미리보기 실행 기능은 `GarmentFitLab`에 둔다. 게임 모듈 및 기존 LaceGarment 모듈을 참조하지 않는다.

프로젝트에는 `Content/Maps/L_GarmentFitLab.umap` 테스트 레벨 하나를 추가한다. 이 레벨은 캐릭터와 플러그인 미리보기 액터를 배치하고 결과를 보여주는 역할만 한다. 사용자가 제공하는 메시의 참조는 테스트 레벨에서 지정하며 플러그인에 특정 `/Game/` 메시 경로를 하드코딩하지 않는다. 플러그인을 끄면 기존 세 레벨은 그대로 사용 가능해야 한다.

새 플러그인·새 테스트 레벨과 플러그인 활성화에 필요한 `LaceLoft.uproject`의 최소 변경만 이 계획의 연결 범위로 삼는다. 기존 루트 `Source/`, 세 레벨과 WBP, `PluginDev/LaceGarmentHost/`, 기존 구현 기록은 변경 대상이 아니다. 기존 독립 호스트 경계 지침을 이 새 플러그인 전체 작업으로 확대 해석하지 않는다. REQ-022로 단계 1 구현이 승인되었으며 구현은 별도 대화에서 수행한다.

최소 테스트 UI는 플러그인의 `Content/UI/WBP_GarmentFitLab.uasset`에 저장한다. 캐릭터·의상 종류 선택, 생성, 배치, 시뮬레이션 실행/정지, 초기화와 옷본·봉제선 표시 정도로 제한한다. 각 단계에 필요한 조작만 추가하며 모든 계층과 배치는 UMG Designer에서 편집한다.

## 데이터 흐름

`캐릭터 → 체형 분석 → 재단 완료 2D 옷본 + 봉제 쌍 → 초기 3D 배치 → UE Cloth 시뮬레이션`

- **체형 분석 결과:** 기준 좌표계·단위, 어깨·가슴·허리·골반·팔의 기준점과 필요한 둘레·길이, 사용한 메시/포즈. 판별할 수 없는 기준점은 명시한다.
- **옷본:** 조각별 ID, 실제 길이 단위의 2D 외곽선, 삼각형, 앞뒤·좌우 의미. 3D 배치나 시뮬레이션이 이 원본을 덮어쓰지 않는다.
- **봉제 쌍:** 두 조각의 대응 경계 구간·방향·샘플 대응. 대응되는 선에 같은 색과 ID를 표시한다. 첫 버전은 의도적인 주름잡기·늘려 봉제하기 없이 대응 길이를 맞춘다.
- **배치:** 몸 주위의 초기 3D 위치. 필요하면 정해진 템플릿에 맞게 조각을 휘어 배치하고, 초기 봉제 경계를 맞춘다. 2D 원본의 길이를 임의로 바꾸어 수렴을 가장하지 않는다.
- **시뮬레이션:** 기본 Chaos Cloth 경로를 사용한다. 원본·초기 배치·시뮬레이션 결과를 구분해 재실행할 수 있게 한다.

## 체형 자동 분석

메시를 제공받으면 먼저 종류, 스케일, 앞/위 방향, 기준 포즈, 골격 유무, 몸 표면과 머리카락·의상 등의 분리 가능 여부를 확인한다. 팔과 몸통이 구별되는 기준 포즈를 우선 사용한다. 실제 메시를 보지 않고 골격 이름·치수·인형 비율을 고정하지 않는다.

골격이 있으면 관절 위치를 체형 기준점 후보로 사용하고 실제 표면 단면으로 둘레를 측정한다. 골격이 없는 메시의 자동 분석 지원 여부는 첫 입력 점검에서 결정한다. 자동으로 판단하지 못한 기준점을 수동 입력했다면 그 부분을 자동인식 성공으로 보고하지 않는다. 초기 버전의 보정은 필요한 기준점·수치에 한정하고 별도 편집기 개발로 확장하지 않는다.

## 두 옷본의 기본 구성

| 의상 | 기본 조각 제안 | 자동 봉제 | 열린 채로 둘 경계 |
| --- | --- | --- | --- |
| 끈 원피스 | 앞판·뒤판·왼쪽 끈·오른쪽 끈 | 좌우 옆선, 각 끈의 앞뒤 연결부 | 상단의 나머지 경계와 밑단 |
| 반팔 셔츠 | 앞몸판·뒤몸판·왼소매·오른소매 | 어깨·몸통 옆선·소매 아래선·앞뒤 진동과 소매산의 대응 구간 | 목둘레·소매 끝·몸판 밑단 |

원피스는 가슴·허리·골반 둘레와 기장·어깨 위치로, 셔츠는 가슴·어깨·목·위팔과 소매 길이로 기본 형식을 계산한다. 여유분과 기장은 확인 가능한 입력값으로 둔다. 실제 옷본 비례와 곡선 규칙은 제공 메시에서 검증하며 2D 표시 단계와 착장 단계의 완료를 구분한다.

## 시뮬레이션의 첫 기술 확인

UE 5.8의 패널 데이터에는 2D/3D 정점과 삼각형을 공급할 수 있고 봉제에는 대응 인덱스를 지정할 수 있다. `AddStitchNode.h:23`은 봉제된 정점이 하나의 3D 정점으로 합쳐진다고 명시한다. 따라서 떨어진 평면 패널이 자동으로 몸을 감싸며 봉제되는 동작을 이미 제공된 기능으로 전제하지 않는다.

먼저 단순한 두 패널을 대응 경계가 맞닿도록 배치해 봉제·중력 변형·초기화가 작동하는지 확인한다. 그 다음 실제 바디 충돌을 확인한다. 이 최소 경로가 막히면 결과와 원인을 검토하고 접근을 조율한다. 자동 체형 분석이나 독자 솔버로 우회하며 장시간 확대하지 않는다. 단순 패널 성공은 두 의상 완성이 아니다.

기술 근거: 설치 엔진 `Engine/Plugins/ChaosClothAsset/Source/ChaosClothAsset/Public/ChaosClothAsset/CollectionClothSimPatternFacade.h:95`, `CollectionClothSeamFacade.h:78`, `Engine/Plugins/ChaosClothAssetDataflowNodes/Source/ChaosClothAssetDataflowNodes/Public/ChaosClothAsset/AddStitchNode.h:23`. 공식 [Cloth 워크플로 개요](https://dev.epicgames.com/documentation/unreal-engine/panel-cloth-editor-overview)는 Cloth Asset·Dataflow·Cloth Component 연결을 설명한다. 자동 체형별 옷본 생성과 실제 실행 성공은 이 문서만으로 보장되지 않으며 새 실험에서 확인한다.

## 결과 확인 방법

각 단계는 사용자가 테스트 레벨에서 재현할 수 있는 상태, 대표 화면, 작동하는 기능, 남은 문제, 다음 선택지를 함께 제시한다. 자동화 통과와 시각적 착장 품질은 별도로 보고한다.

옷본 단계에서는 조각 형상·자기교차·봉제 쌍 누락·방향·길이 대응과 열려 있어야 할 경계를 확인한다. 시뮬레이션 단계에서는 봉제 벌어짐, 몸 관통, 뒤집힘, 과도한 늘어남, 안정화와 초기화 재현을 확인한다. 고정 포즈에서 10초 실행하고 정면·측면·후면을 남기며, 길이 변화·봉제 간격·관통 측정의 범위와 한계를 기록한다. 임시 고정점은 화면에 표시하고, 임시 지지 상태를 자연스러운 착장 완료로 보고하지 않는다.

초기 목적은 구현 수준의 확인이다. 부족한 부분도 화면과 지표로 드러내고 다음 보완 범위를 사용자와 정한다. 품질 기준을 몰래 낮추거나 완벽한 범용 시뮬레이터를 이번 완료 조건으로 추가하지 않는다.
