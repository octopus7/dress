# LaceLoft 의상 제작 전체 설계

작성일: 2026-10-15. 근거: [REQ-003~006](../REQUESTS.md). 이 문서는 구현 대상의 설계이며, 아래 기능이 이미 구현되었다는 의미는 아닙니다.

## 1. 목표와 확정 사항

사용자가 반팔 티셔츠 또는 돌핀쇼츠 옷본을 선택하고, 지정된 선을 따라 재단하고, 안내된 봉제선을 바느질하여 완성한 옷을 흰 더미 인형에 입힌 뒤 포즈를 취할 수 있게 합니다.

- UE 5.8 C++, Windows 데스크톱, 마우스/키보드 우선.
- 인형은 OB11 계열의 큰 머리·짧은 몸 비율을 가진 실제 Skeletal Mesh.
- 인형의 UV는 나중에 전신을 균일하게 칠할 수 있는 독립적인 원본 작업물로 완성.
- 재단은 지정선 방식. 자유 선 그리기/임의 패턴 변형은 이번 범위에 넣지 않음.
- UMG는 모두 실제 Designer 편집 가능한 WBP. 클래스 내부 위젯 트리 생성 금지.
- 현재 세 레벨과 이동 기능을 확장하며, 기존 이동 경로를 유지.
- 실제 구현은 별도 Astra (`gpt-6-astra`) / High 대화에서 수행. 이 대화는 설계·관리만 담당.

## 2. 구현 방식 선택

| 방식 | 장점과 비용 | 결정 |
| --- | --- | --- |
| 지정선 재단·봉제 상태 + 동일 옷본에서 제작한 Cloth Asset | 작업 판정이 명확하고, 제작 결과와 3D 형상 연결을 검증할 수 있음 | 채택 |
| 게임 실행 중 임의 메시 생성·자유 봉제·완전한 천 조립 | 자유도는 높지만 토폴로지 변경, 충돌, 봉제 솔버가 별도 대형 과제 | 현재 범위 아님 |
| 완성된 스킨 의상 표시만 사용 | 개발은 빠르지만 천의 움직임을 검증할 수 없음 | 제작 중 임시 확인용만 허용 |

**이번 버전의 실제 동작:** 재단과 봉제는 사용자의 입력을 선 구간 단위로 기록하는 제작 작업입니다. 미완성 상태는 2D 작업대에서 조각을 정렬하고, 목표 위치의 반투명 윤곽과 연결된 봉제선을 표시하는 조립 미리보기로 보여줍니다. 필수 봉제가 완료되면 해당 옷본으로 제작한 완성 3D 의상을 장착하고 천 시뮬레이션을 적용합니다. 미완성 천을 인형 위에서 실 하나씩 물리적으로 꿰매거나 옷을 머리 위로 당겨 통과시키는 과정은 포함하지 않습니다.

UI 옷본과 무관하게 모델링한 옷으로 바꾸는 방식은 사용하지 않습니다. 옷본의 PieceId/EdgeId/SeamId와 동일한 원본에서 2D 표시, 작업 판정, 3D 패널, 봉제 대응, 의상 UV를 연결합니다. 형상/봉제 데이터가 바뀌면 의상 애셋을 다시 제작하고 버전을 올립니다.

Cloth는 에디터에서 제작하고 게임에서는 저장·쿠킹된 애셋을 사용합니다. Epic이 문서화한 Panel Cloth의 흐름도 에디터의 Dataflow 제작, 스킨 웨이트 전이, Physics Asset 설정, 게임의 Cloth Component 실행입니다. [공식 Panel Cloth 개요](https://dev.epicgames.com/documentation/en-us/unreal-engine/panel-cloth-editor-overview)

## 3. 레벨별 사용자 흐름

| 레벨 | 구성과 동작 |
| --- | --- |
| `L_Title` | 새 제작, 이어하기, 입어보기, 기존 이동 버튼. 저장이 없으면 이어하기 비활성화 |
| `L_GarmentCreation` | 의상 선택 → 옷본/조각 확인 → 재단 → 조각 정리 → 봉제 → 완성 확인 → 입어보기 |
| `L_FittingRoom` | 흰 더미, 완성한 상의/하의 장착·해제, 카메라 회전/줌, 포즈 선택·관절 조절·초기화 |

제작 화면은 좌측 조각/단계 목록, 중앙 확대·이동 가능한 작업대, 우측 현재 작업 안내, 하단 도구/취소·다시 실행으로 구성합니다. 재단 중에는 활성 경로, 진행 구간, 남은 구간을 구분합니다. 봉제 중에는 대응하는 두 가장자리와 진행 방향을 함께 보여줍니다.

레벨 이동 전에 작업 상태를 저장합니다. 완료되지 않은 의상은 입어보기의 장착 목록에 포함하지 않습니다. 제작을 취소하거나 다른 옷본을 선택해도 저장된 다른 작업물과 완성 의상은 유지합니다.

## 4. 흰 더미 인형 제작 기준

### 4.1 형상·크기·원본

- 원본 `.blend`, FBX, 치수표, 정면·측면·후면 검수 이미지를 함께 보관합니다.
- 큰 둥근 머리와 짧은 몸통·사지, 얼굴·머리카락·장식 없는 흰 더미로 제작합니다.
- 초기 작업 기준은 **전체 높이 15cm, 약 3등신**으로 제안합니다. 이것은 LaceLoft의 작업값이며 특정 OB11 상품의 실측 규격이나 호환 보장이 아닙니다. 정면/측면 실루엣을 검수한 뒤 이 값을 기준 데이터로 고정합니다.
- 관절은 간결한 인형 관절 느낌을 내되, 옷과 접촉하는 어깨·겨드랑이·골반에 큰 틈과 돌출이 생기지 않게 만듭니다. 내부 기계 구조는 만들지 않습니다.
- 몸·의상·충돌체는 같은 좌표계와 단위를 사용합니다. UE는 cm, 옷본 원본은 mm, 변환은 `cm = mm / 10` 한 곳에서 수행합니다.
- UE 컴포넌트 스케일 `(1,1,1)`, 바닥에 발바닥 정렬, root 원점, 전방 +X / 위 +Z를 검증합니다. 크기를 확대해 물리 문제를 숨기지 않습니다.
- 치수표는 실제 완성 메시에서 키, 목·가슴·허리·엉덩이 둘레, 어깨 폭, 팔·다리 길이를 측정하여 작성합니다. 옷본 치수는 이 표를 사용합니다.

### 4.2 골격·웨이트

- 기준 자세는 대칭 A포즈. 팔 각도는 초기 약 40°이며 원본/FBX/UE에서 일치시킵니다.
- 필수 뼈: root, pelvis, spine_01, chest, neck, head, 양쪽 clavicle/upperarm/forearm/hand, thigh/calf/foot. 손가락 개별 조절·표정 리깅은 이번 범위 아님.
- 몸은 하나의 Skeleton을 공유하며, 제어용 본과 실제 변형용 본을 구분합니다.
- 미할당 정점 0, 웨이트 정규화, 초기 정점당 최대 4개 영향. 필요한 추가 twist 본은 어깨 변형 검증 결과에 따라 결정합니다.
- A포즈, 팔 들기, 팔 앞으로, 팔꿈치/무릎 90°, 앉기, 고개 회전을 **UE 임포트 결과**에서 확인합니다. 분리된 파트, 접힌 면, 관절 붕괴가 없어야 합니다.
- 수동 검수한 Physics Asset을 만들고 머리·몸통·골반·상완·전완·허벅지·종아리의 천 충돌을 확인합니다.

### 4.3 UV와 나중의 도색

흰색으로 보인다는 이유로 UV 작업을 생략하거나 자동 투영 결과만 납품하지 않습니다.

| 항목 | 제작/검수 기준 |
| --- | --- |
| 채널 | 모든 페인트 대상 표면을 UV0에 할당. 0..1 단일 atlas, 기본 2048×2048 |
| 고유 영역 | 좌우 팔·다리·손발·머리를 겹쳐 쌓지 않음. 서로 다른 메시 파트도 동일 텍스처에서 고유 영역 사용 |
| 누락/겹침 | 누락 면, 면적 0 UV 삼각형, 서로 다른 면의 UV 내부 겹침 0. 공유 경계는 허용 |
| 균일 밀도 | 실제 표면 면적을 기준으로 island 크기를 맞춤. 주요 island 평균 texel density를 전체 기준의 ±10% 이내로 맞추고 예외가 있다면 수치와 이유 기록 |
| 늘어짐 | 체크무늬의 크기와 방향으로 머리·몸통·관절·손발을 검수. 밀도 일치만으로 국소 왜곡 검사를 대체하지 않음 |
| seam | 뒤통수·목 아래·사지 안쪽 등 덜 보이는 곳을 우선. 도색하기 쉬운 앞면을 불필요하게 잘게 나누지 않음 |
| 여백 | 초기 2K 기준 island 간 32px, atlas 외곽 16px, 색상 확장 16px. 실제 packing 후 측정하고 1K/512px 축소와 UE 필터링에서 색 번짐 확인 |
| 도색 시험 | 좌우가 다른 문자/색을 칠했을 때 반대편에 복제되지 않음. 동일한 표면 크기의 체크무늬가 부위별로 비슷한 크기로 보임 |
| 전달물 | UV layout PNG, 체크무늬 정·측·후면 이미지, UV 수치 검사 결과, 흰 BaseColor PNG, `.blend` 원본 |

밀도 측정식은 `D = R × sqrt(Auv / Acm²)` px/cm를 사용합니다. R은 atlas 한 변의 해상도입니다. 구형 머리를 완전히 무왜곡으로 펼칠 수는 없으므로 seam 위치와 국소 늘어짐을 함께 검수합니다. 초기 목표 수치는 프로젝트의 합격 기준이며 엔진의 보장값이 아닙니다.

Blender의 Average Island Scale과 Minimize Stretch를 활용하되, 도구 실행 자체를 검수 완료로 간주하지 않습니다. [Blender UV 편집 문서](https://docs.blender.org/manual/id/5.0/modeling/meshes/uv/editing.html)

흰 재질에는 `BaseColorTexture`, `Tint`, `Roughness` 파라미터를 둡니다. 초기 BaseColor는 흰색, Metallic은 0이며 조명/그림자를 텍스처에 구워 넣지 않습니다. 추후 텍스처 교체로 전신 도색을 적용할 수 있게 합니다. 게임 내 실시간 브러시 페인팅 기능 자체는 후속 범위입니다.

## 5. 두 의상의 옷본

| 의상 | 기본 조각 | 봉제/마감 |
| --- | --- | --- |
| 반팔 티셔츠 | 앞판 1, 뒤판 1, 소매 좌/우 각 1, 목 시보리 1 | 어깨 → 소매 부착 → 옆선/소매 아래 → 목 시보리 → 소매/몸판 밑단 |
| 돌핀쇼츠 | 앞판 좌/우 각 1, 뒤판 좌/우 각 1, 허리밴드 1, 다리별 밑단 바인딩 | 앞/뒤 밑위 → 안쪽 다리 → 옆선(트임 제외) → 허리밴드 → 곡선 밑단/트임 바인딩 |

옷본마다 재단 외곽, 봉제선, 시접, 결 방향, 좌우 구분, notch, 봉제 방향, 접히는 선, 열린 경계를 포함합니다. 목·팔·허리·다리 입구를 막아 봉제하지 않습니다. 돌핀쇼츠의 둥근 밑단과 옆트임을 실루엣에서 구분할 수 있어야 합니다.

시접은 초기 3mm를 출발값으로 잡되 목 시보리와 곡선 바인딩은 실제 인형 크기에 맞춰 검수합니다. 시접 바깥 재단선과 실제 봉제선이 다른 데이터임을 유지합니다. 밑단은 접어 박는 작업, 바인딩은 별도 조각 부착, 시보리/허리는 의도한 길이비를 가진 작업으로 모델링합니다.

봉제 짝은 단순 길이 동일 여부만 검사하지 않습니다. 일반 봉제는 기준선 길이를 맞추고, 목 시보리 등 의도적 차이는 `EaseRatio`와 종류로 기록합니다. 가능한 오류를 UI에서 설명하고 잘못된 조합은 진행시키지 않습니다.

큰 머리 때문에 착장은 완성 의상을 기준 포즈의 몸에 배치하는 방식으로 합니다. 머리를 통과시키는 물리 시뮬레이션 또는 실제 인형에 입히기 위한 여밈 구조는 현재 완료 조건에 포함하지 않습니다.

## 6. 데이터와 상태

- `ULaceLoftPatternDefinition`: 읽기 전용 옷본 Data Asset. PatternId/Version, 인형 치수 버전, 조각, 경로, 봉제 작업, 의상 애셋 참조, 원본 hash.
- `FLaceLoftPatternPiece`: PieceId, mm 좌표 외곽/봉제선, 재단 경로, notch, 결 방향, 패턴 표시/의상 UV 대응.
- `FLaceLoftSeamOperation`: SeamId, 종류(두 경계 연결/접어박기/바인딩), PieceId와 EdgeId의 짝, 방향, EaseRatio, 선행 작업.
- `FLaceLoftGarmentProject`: ProjectId, PatternId/Version, 진행 상태, 경로별 완료 구간, 봉제 상태, 작업대 조각 배치, 완성 결과 ID.
- `ULaceLoftWardrobeSubsystem`: GameInstance 수명의 여러 작업물·완성 의상·착장 슬롯·현재 포즈 상태 관리. 레벨 UObject 포인터를 저장하지 않음.
- `ULaceLoftSaveGame`: schema version, 작업물 배열, 장착한 상의/하의 ID, 포즈 ID/조절값. 버전 불일치·누락 애셋·손상 파일은 복구 안내 후 기본 상태 사용, 기존 파일을 즉시 덮어쓰지 않음.

상태 흐름은 `PatternSelected → Cutting → PiecesReady → Sewing → Completed`입니다. 선행 단계가 충족되지 않으면 다음 단계로 넘어가지 않습니다. Undo/Redo는 한 번의 스트로크나 봉제 작업을 단위로 처리합니다. 뒤 단계가 성립하지 않게 만드는 취소는 종속 상태와 완성 여부를 함께 되돌립니다.

완성 결과는 원본 ProjectId/PatternVersion과 연결합니다. 완성 후 Undo로 조건이 깨지면 해당 결과의 장착 자격을 취소하고 현재 입고 있다면 해제합니다. 다른 작업물의 완성 결과에는 영향을 주지 않습니다. 저장을 읽을 때도 저장된 Completed/해금 플래그만 신뢰하지 않고 실제 작업 상태와 버전으로 자격을 재검증합니다.

## 7. C++ / WBP 역할

| 계층 | 책임 |
| --- | --- |
| C++ 데이터/로직 | 단위 변환, 경로 투영/진행 판정, 봉제 조건, 상태 전환, Undo/Redo, 저장, 착장, 포즈·카메라 명령 |
| 실제 WBP | 패널·버튼·목록·텍스트·스타일·레이아웃·기본값. Designer에서 수정 |
| 옷본 뷰 | WBP 안의 실제 뷰 위젯에서 데이터 기반 선/조각 표시 및 입력 변환. Designer에서도 선택한 예제 옷본을 미리 볼 수 있게 함 |
| 월드 애셋 | 인형 Skeletal Mesh, Skeleton, Physics Asset, 의상 Cloth Asset, Pose Asset/Control Rig, 조명·카메라 |

기존 `WBP_Title`, `WBP_GarmentCreation`, `WBP_FittingRoom`은 유지합니다. 새 제작/착의 부모 클래스는 공통 이동 부모를 상속하여 `TitleButton`, `CreationButton`, `FittingButton` 계약을 유지합니다.

추가 WBP는 `WBP_PatternWorkspace`, `WBP_PatternPieceEntry`, `WBP_SewingStepEntry`, `WBP_GarmentEntry`, `WBP_PoseControls`, `WBP_ConfirmDialog`로 제한합니다. 목록 항목은 설정된 실제 WBP 클래스로 생성합니다. C++에서 버튼/패널을 ConstructWidget으로 조립하지 않습니다. 옷본 도형을 그리는 행위와 위젯 계층 생성은 구분하되, 도형의 원본 데이터/미리보기도 에디터에서 확인할 수 있어야 합니다.

## 8. 착의·포즈·천

- `ALaceLoftDummyActor`에 인형 SkeletalMesh, 상의/하의 의상 컴포넌트, 포즈 제어를 구성합니다.
- Cloth Component는 인형 SkeletalMeshComponent에 연결하고 해당 skeleton 및 Physics Asset과 맞춥니다. 저장된 Cloth Asset은 `SetAsset()`으로 장착합니다.
- 티셔츠 어깨/목과 쇼츠 허리의 부착 영역을 지정하고 나머지는 필요한 만큼 천으로 움직이게 합니다. 의상별 시뮬레이션 메시와 렌더 메시를 구분합니다.
- 중립, 팔 들기, 팔 앞으로, 앉기 등의 포즈 프리셋과 주요 관절의 제한된 회전 조절을 제공합니다. 관절별 한계를 데이터로 관리하고 초기화 버튼을 둡니다.
- 장착·큰 포즈 전환 시 cloth reset/teleport, 안정화 시간을 적용합니다. 상의와 하의를 동시에 입혔을 때 허리 겹침을 별도로 검사합니다. 서로 다른 Cloth Component 사이 충돌을 자동으로 보장한다고 가정하지 않습니다.
- 첫 수직 검증에서 작은 인형 스케일의 충돌 두께/메시 해상도/포즈 안정성을 확인합니다. 두 의상 사이 관통이 남으면 동일 collection으로 합친 조합 애셋 또는 접촉 부분의 skin/anim-drive를 검증하여 선택합니다. 별도 시스템을 추가하거나 천을 비활성화해 문제를 숨기지 않습니다.
- 카메라는 인형 중심 회전·줌·초기화를 제공하며 UI 조작과 구분합니다. UIOnly 입력을 유지하면서 WBP의 미리보기 입력 영역에서 카메라 명령을 전달할 수 있습니다. 일반 캐릭터 이동 기능은 추가하지 않습니다.

## 9. 완료 조건

1. 두 옷본 모두 선택 → 지정선 재단 → 봉제 → 완성 → 착의의 전체 흐름을 통과.
2. 실제 OB11 계열 흰 더미 Skeletal Mesh와 원본/골격/웨이트/충돌/UV 검수 자료 존재.
3. UV0 고유 배치와 밀도·왜곡·도색 시험 통과. 좌우 도색이 서로 독립적.
4. 상·하의 동시 착용과 정해진 포즈에서 의상·몸 충돌 검수, 천 시뮬레이션 실행.
5. 제작 도중 레벨 이동, 앱 종료 후 복원, 작업 취소/다시 실행이 진행률과 의상 해금을 일관되게 유지.
6. WBP Designer에서 UI를 수정하고 Blueprint Compile/Save 성공. 클래스의 위젯 트리 생성 코드 없음.
7. Editor/Game 빌드와 자동화 통과, Win64 패키지에서 두 의상 제작·착의·포즈 확인.

## 10. 첫 버전에서 다루지 않는 기능

자유 재단, 임의 봉제 조합, 실/바늘의 완전한 물리, 천 뒤집기, 머리를 통과시키는 착의, 체형 슬라이더, 여러 인형 규격, 게임 내 도색 브러시, 멀티플레이, 상점·공유·온라인 기능. UV와 재질 구조는 추후 도색 확장을 막지 않게 준비합니다.
