# 사용자 요청 문서

사용자가 요청한 프로젝트 요구사항과 작업 지침을 기록합니다. 기록 여부는 [요청 기록 제외 기준](REQUEST_LOG_EXCLUSIONS.md)을 따릅니다. 새 요청은 날짜와 함께 아래에 추가하고, 기존 요청을 변경하는 경우 해당 항목과의 관계를 명시합니다.

## REQ-001 — LaceLoft 기본 프로젝트 생성 (2026-10-15)

- Unreal Engine **5.8 C++** 프로젝트를 만들고 이름은 **LaceLoft**로 합니다.
- **타이틀**, **의상 제작**, **의상 입어보기(포즈 취하기)** 세 레벨로 구성합니다.
- 별다른 콘텐츠 없이 이동용 UMG 위젯만 만들고 UI/레벨 전환을 처리합니다.
- UMG WBP는 실제 애셋으로 저장되어야 합니다.
- 다음 UMG 지침을 별도 Markdown 파일에 작성하고 `AGENTS.md`에서 연결합니다.

> 내가 지시하지 않는다면 클래스 코드 내부에서 위젯 트리를 구성하지 않는다 항상 위젯 에디터에서 보면서 수정 가능한 애셋 상태여야한다

관련 지침: [UMG_GUIDELINES.md](UMG_GUIDELINES.md)

## REQ-002 — 사용자 요청 기록 규칙 (2026-10-15)

- 요청 문서를 하나 만들고, 사용자가 요청한 내용을 그 문서에 기록하도록 작업 지침에 반영합니다.
- 요청 문서에 기록하지 않을 내용을 정의하는 별도 Markdown 파일을 만듭니다.
- **사소한 수치 조정**, **레벨 내 사소한 배치 조정**을 기록 제외 대상으로 지정합니다.

관련 기준: [REQUEST_LOG_EXCLUSIONS.md](REQUEST_LOG_EXCLUSIONS.md)

## REQ-003 — 옷본 제작·재단·봉제·착의 (2026-10-15)

REQ-001의 기본 프로젝트에 이어 구현할 기능입니다. 최초 문의 시에는 답변만 요청했으며, 이후 REQ-004에서 전체 계획 작성을 요청했습니다.

- 제작 UI에서 간단한 옷본을 제공하고 사용자가 재단하고 바느질합니다.
- 만든 옷을 마네킹에 입히며, 마네킹은 오비츠와 비슷한 비율의 스켈레탈 메시를 사용합니다.
- 제공할 옷본은 **반팔 티셔츠**, **돌핀쇼츠**입니다.

## REQ-004 — 전체 구현 계획과 흰 더미 인형 UV (2026-10-15)

- REQ-003에 대한 전체 구현 계획을 작성합니다.
- 인형은 **흰 더미 인형**으로 만듭니다.
- 나중에 텍스처를 균일하게 칠할 수 있도록 UV를 제대로 할당합니다. 흰색 재질만 설정하고 UV 작업을 생략해서는 안 됩니다.

## REQ-005 — 체형과 재단 방식 확정 (2026-10-15)

REQ-003~004의 구체화입니다.

- 인형 비율: **OB11 계열 — 큰 머리와 짧은 몸**.
- 재단 방식: **정해진 재단선을 따라 자르기**.

## REQ-006 — 설계/관리와 실제 구현 대화 분리 (2026-10-15)

- 현재 대화는 **작업 관리와 설계 전용**으로 사용합니다.
- 실제 구현은 **별도의 새 대화**에서 진행합니다.
- 구현 모델은 **Astra**, 추론 강도는 **High**입니다.

계획 문서: [전체 설계](Design/LACELOFT_DESIGN.md), [단계별 구현 계획](Plans/2026-10-15-laceloft-garment-workflow.md)

## REQ-007 — 별도 구현 대화에서 확장 실행 및 검증 기록 (2026-10-16)

REQ-003~006의 실행 요청입니다.

- 지정된 Astra / High 구현 대화에서 새 계획의 0~9단계를 순서대로 구현·검증합니다.
- 기존 미커밋 작업을 보존하고 `Docs/Implementation/STATUS.md`에 단계 상태와 실제 검증 근거를 기록합니다.
- 전체 아트를 완성하기 전에 실제 인형 크기의 Chaos Cloth와 Win64 패키지 동작을 검증합니다.
- 완성 후 Undo와 저장 복원 시 작업물별 장착 자격을 다시 검증합니다.
- `.blend`/FBX/UV 이미지/치수표/공통 옷본 데이터와 실제 UE 애셋을 보존합니다. 미검증 결과는 완료로 보고하지 않습니다.

## REQ-008 — 외부 저작툴을 통한 독립 의상 파일·배포 플러그인 (2026-10-16)

- 외부 저작툴을 이용하는 플러그인을 설계합니다.
- 옷 애셋을 프로젝트 의존성이 없는 파일로 저장하여 다른 사람에게 전달할 수 있어야 합니다.
- ZIP으로 패키징하여 여러 전달 수단으로 배포할 수 있어야 합니다.
- 수신자는 UE **5.8 새 프로젝트**에서 플러그인을 활성화하여 사용할 수 있어야 합니다.
- 추후 구현은 기존 LaceLoft 구현 대화와 **별개의 새 대화**에서 진행하고, 추론 강도는 기존 구현 대화와 같은 **High**로 합니다. REQ-006의 Astra 모델 방침을 유지합니다.
- 최초 요청에서는 의도 이해 여부만 답하고 구체적인 설계·구현은 하지 않도록 했습니다. 후속 요청 범위는 REQ-009를 따릅니다.

## REQ-009 — 플러그인은 현재 설계만 진행 (2026-10-16)

REQ-008의 후속 지시입니다.

- 현재는 **설계만** 작성합니다.
- 플러그인 코드·애셋 구현이나 새 구현 대화 생성은 이번 작업에 포함하지 않습니다.
- 기존 LaceLoft 구현 대화의 작업 범위를 이번 플러그인 설계로 확장하지 않습니다.

설계 문서: [플러그인 설계](Design/LACE_GARMENT_PLUGIN_DESIGN.md), [독립 의상 파일 계약](Design/LACE_GARMENT_PACKAGE_FORMAT.md).

## REQ-010 — 외부 저작툴 Blender로 한정 (2026-10-16)

REQ-008~009의 지원 범위 확정입니다.

이 저작 구조는 후속 REQ-011에서 UE 플러그인 단독 저작으로 대체되었습니다. 아래는 이전 요청 기록입니다.

- 외부 저작툴은 **Blender만** 지원합니다.
- 다른 저작툴의 연결·애드온·전용 변환기는 현재 설계와 구현 범위에 넣지 않습니다.

## REQ-011 — UE 5.8 플러그인만으로 독립 저작 (2026-10-16)

REQ-008의 외부 저작툴 중심 구조와 REQ-010의 Blender 애드온 필수 구조를 변경합니다.

- Blender 자체에 큰 의존성을 두지 않습니다.
- **UE 5.8 플러그인만으로 의상을 독립적으로 저작**할 수 있게 합니다.
- 단순히 외부에서 완성한 옷을 UE 애셋으로 변환하는 도구에 그치지 않고, UE 안에서 옷본 작성·편집, 봉제 지정, 의상 생성과 저장을 수행하는 방향으로 설계를 수정합니다.
- 프로젝트와 무관한 파일 저장, ZIP 배포, 새 UE 5.8 프로젝트 사용 요구는 유지합니다.
- 현재는 REQ-009의 **설계만 진행** 범위를 유지합니다. 기존 게임 구현 대화와 별개이며, 새 구현 대화를 생성하거나 코드·애셋을 구현하지 않습니다.

## REQ-012 — 별도 Astra / High 대화에서 플러그인 구현 시작 (2026-10-16)

REQ-011의 UE 단독 저작 설계에 대한 실행 요청입니다. REQ-009 및 REQ-011의 당시 설계 전용 제한을 이번 플러그인 구현 대화에 한해 해제합니다.

- 예정한 **별도의 새 구현 대화**를 만들고 수정된 설계와 실행 지시를 전달합니다.
- 모델은 **Astra (`gpt-6-astra`)**, 추론 강도는 **High**로 유지합니다.
- UE 5.8 플러그인만으로 저작·독립 파일 저장·애셋 생성·ZIP 배포하는 최신 설계를 구현합니다. Blender 애드온 중심의 이전 설계를 실행하지 않습니다.
- 기존 LaceLoft 게임 구현 대화와 분리하고, 현재 대화는 계속 설계·작업 관리를 담당합니다.
- 구현 상태와 실제 검증 근거를 별도로 기록합니다. 설계의 검증 관문을 통과하지 않은 기능은 완료로 보고하지 않습니다.

전달한 구현 대화 ID: `01a14073-fb57-76d2-bf43-db08097d8770` (로컬 `dress` 프로젝트, `gpt-6-astra` / `high`). 기존 게임 구현 대화 ID `01a14019-82ac-7f20-a34b-a20f53c96744`와 구분합니다.

- 플러그인 진행상황을 **완료 태스크 수 기준 비율**과 **예상 작업량을 반영한 비율**로 각각 알려달라는 조회 요청입니다.
- 완료 기록과 진행 중인 부분 구현을 구분하고, 작업량 기준 비율은 추정임을 표시합니다. 플러그인의 구현 범위를 추가하는 요청은 아닙니다.

## REQ-017 — 이번 플러그인 구현 대화의 완료 목표 축소 (2026-10-16)

REQ-012의 이번 실행 범위를 조정합니다. 대상은 플러그인 구현 대화 `01a14073-fb57-76d2-bf43-db08097d8770`입니다.

- 첨부한 목록의 네 항목을 **이번 대화의 완료 목표에서 제외**합니다: Task 4 독립 원본 파일 저장·열기, Task 5 실제 저작 WBP/EUW, Task 6 콘텐츠 팩·배포·cook, Task 7 새 프로젝트 최종 인수.
- **Task 1 독립 호스트·패널 생성, Task 2 봉제·안정화·Cloth 생성, Task 3 바디·대표 의상·문서 모델만 계속 진행**합니다.
- 제외한 항목은 후속 범위로 보존하며 이번 완료를 막는 조건으로 삼지 않습니다. 기존 작업물이나 검증 기록을 삭제하라는 요청은 아닙니다.
- 남은 생성 기능에 필요한 호스트 Editor 빌드·자동화·UE 애셋 저장/재열기·대표 의상 착장/포즈 검증은 유지합니다. 독립 `.lgarment` 파일 기능과 UE 애셋 저장 검증을 구분합니다.
- 향후 진행률은 이번 활성 Task 1~3을 분모로 보고하며, 전체 제품 범위와 혼동하지 않습니다.

## REQ-018 — 커밋 불필요 항목의 Git 제외 규칙 (2026-10-16)

- 저장소의 `.gitignore`를 정리하여 UE 생성물·로컬 IDE 상태·Python 캐시·Blender 자동 백업·OS 메타데이터를 제외합니다.
- 실제 `Content` 애셋, 코드·설정·프로젝트 파일, 제작 원본·검증 입력과 문서는 커밋 대상으로 유지합니다.
- 후속 지시에 따라 생성된 `ArtSource/**/QA/` 이미지와 `UVValidation.json`, `PaintValidation.json` 검증 보고서도 제외합니다. 검증 스크립트와 입력 텍스처는 유지합니다.
- 기존 파일 삭제나 커밋은 수행하지 않습니다.

## REQ-019 — 게임 작업을 파일 단위로 단계별 커밋 분리 (2026-10-16)

- 별도 플러그인 작업을 제외하고 기존 게임 작업을 단계별 커밋으로 나누는 방향을 검토합니다.
- 첫 커밋은 최초 프로젝트 골격과 `.gitignore`를 묶고, 실제 의상 작성·착용 구현은 제외하는 구성입니다.
- 과거 작업 상태를 정확히 재구성할 필요 없이 현재 파일을 대략적인 역할별로 묶으면 충분합니다.
- 후속 요청에 따라 계획 0–9의 게임 구현 전체가 커밋 이력에 포함되도록 남은 코드·원본 애셋·검증 도구·문서를 함께 커밋합니다. 현재 반영된 치트 완성 버튼과 와이어프레임 보기 변경도 포함합니다.
- 별도 플러그인 코드·애셋·전용 도구·전용 문서와 `.gitignore`에 지정된 생성물·QA 결과물은 계속 제외합니다.

## REQ-020 — 작은 기능 목표별 확인과 후속 작업 조율 (2026-10-17)

- 현재 진행 중인 구현은 그대로 둡니다. 이번 요청으로 실행 중인 작업을 중단하거나 범위를 변경하지 않습니다.
- 이후 작업은 작은 기능별 목표로 나누고, 각 기능의 실제 결과와 구현 완성도를 사용자와 확인한 뒤 다음 작업의 범위와 우선순위를 조율합니다.
