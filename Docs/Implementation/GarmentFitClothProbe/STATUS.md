## 실행 중 발견·수정한 문제

- 샌드박스 안에서 엔진 배치 경로 검사가 실패했다. 승인된 외부 실행으로 빌드를 수행했다. 설치 엔진 파일은 수정하지 않았다.
- 최초 타깃의 V6 빌드 설정이 설치 5.8.3의 V7과 불일치했다. 전용 타깃을 V7으로 수정했다.
- 최초 테스트 fixture가 같은 TArray 요소 참조를 다시 Add해 assert했다. 값 복사로 수정 후 두 테스트가 각각 유효 입력 미구현과 네이티브 실험 미구현 때문에 실패하는 RED를 확인했다 (`Saved/Probe/Red/index.json`: 0 성공/2 실패). 이후 실제 구현으로 통과했다.
- 두 번째 Create에서 이미 존재하는 패키지를 완전히 로드하지 않아 저장이 거부됐다 (`Runs/20261017-021331-638/Create-Report`: 1 성공/1 실패). `FullyLoad` 후 객체를 재사용하도록 수정했다. 이어 비동기 PostLoad가 끝나기 전에 Build가 재질 배열을 재설정하는 경고가 있어, 기존 패키지 로드 뒤 asset compilation 완료를 기다리도록 했다. 최종 전체 실행에서 경고 없이 통과했다.
- Cloth 표면 표시 검사 추가 때 protected override 직접 호출로 생긴 컴파일 오류는 공개 SceneComponent 인터페이스 호출로 수정했다. 최종 빌드와 두 프로세스 검증은 모두 통과했다.
- 호스트 시작 시 불필요한 기본 플러그인이 설정을 자동 작성했다. AndroidFileServer/EnhancedInput을 전용 프로젝트에서 비활성화하고, 여전히 엔진이 자동 기록하는 DefaultInput.ini만 호스트 내부 제외 규칙에 넣었다. 공유 `.gitignore`나 메인 설정은 수정하지 않았다.

## 검토와 경계 판단

`requesting-code-review` 절차의 별도 Astra/xhigh 읽기 전용 검토 결과 Critical 0 / Important 0 / Minor 0. 설치 엔진의 실제 seam 용접/solver 경로, 실측 검증, 원본 보존, 경로 격리를 검토했다. 이후 발견한 비동기 PostLoad 경고와 표시 검사 변경은 최종 빌드/전체 자동화로 검증했다. 검토자는 빌드/화면을 대신 확인하지 않았으며 위 실행/화면 확인은 구현 담당이 직접 수행했다.
