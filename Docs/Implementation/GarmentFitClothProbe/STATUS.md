## REQ-029 — 실제 천 표면 캡처 누락 수정

2026-10-17. 기존 독립 호스트의 캡처 경로에서 두 원인을 수정했다. 천의 원본 메시·재질·물리 설정은 바꾸지 않았다.

- **첫 재질 캡처 누락:** 글로벌 shader compile 작업이 0개여도 on-demand shader map은 미완성일 수 있었다. 첫 fixture 순서를 바꾸면 누락도 함께 이동했다. `UMaterialInterface::EnsureIsComplete()`로 실제 사용 재질의 필요한 셰이더를 완성한 뒤 PSO·렌더 프록시를 준비한다.
- **바디 천의 검은 표면:** 깊이에는 25,062픽셀의 천이 있고 BaseColor도 정상이나, 유효한 법선 `(0,-1,0)`이 기본 단방향 광원에서 빛을 받지 못했다. 기본 미리보기에는 ambient cubemap도 없었다. 캡처 동안 반대편 보조광을 추가해 양쪽 면을 비춘다. 노출 변경만으로는 해결되지 않았으며, 최종 캡처는 물리 카메라 기본값에 의존하지 않는 수동 노출을 쓴다.
- **실패 검출:** 회귀·봉제·바디 핀·통합의 모든 캡처에 검사선 없는 `*-surface.png`와 실제 Cloth Component만 있는 `*-surface-cloth-only.png`를 저장한다. 후자의 픽셀 면적이 1,000 미만이면 자동화가 실패한다. 마네킹·충돌 표시물·검사선은 show-only 목록에서 제외한다.

아래는 REQ-026 완료 당시 기록이다. 천 표면 표시 한계의 후속 수정·검증은 위 REQ-029를 따른다.

### 구현 결과

- **봉제:** 원본 2D 호 길이와 경계 방향을 사용한다. 서로 다른 정점 수/간격은 원본 정점과 인덱스를 유지하면서 경계를 추가 분할한다. `EqualOnly`와 `NormalizedArcLength` 정책을 구분하며 100:150, 150:100 경계도 실제 native XPBD의 2D rest metric으로 시뮬레이션했다. 원본 길이를 암묵적으로 변경하지 않는다.
- **바디 핀:** 천의 패널 로컬 원본 정점 → 용접된 native 입자 → 바디 삼각형/무게중심 좌표/표면 오프셋을 연결한다. native `MaxDistance=0` 입자가 바디의 강체 이동·회전을 따라간다. 생성·활성/비활성·해제·초기화·직렬화·재열기를 지원한다. 해제/비활성화는 native 질량 재설정을 위해 cloth asset/proxy를 교체하며 위치와 속도의 연속성을 보장하지 않는다.
- **통합:** 봉제된 경계의 정점을 바디에 고정한 최소 예제를 검증했다. 두 패널의 seam alias가 같은 입자로 해석되며 입력 봉제 애셋의 원본 2D/초기 3D/용접 lookup은 그대로 유지한다.
- **독립 마네킹:** 안정 커밋 `69583eb`의 FBX blob `8d7916124c01666172a92bbb4b424dfbaa9d0237`를 고정 추출해 실험 안에 정적 바인드 포즈 메시로 임포트했다. 실제 저장 패키지의 hard/soft dependency를 검사해 메인 `/Game/`, `GarmentFitLab`, `LaceGarment` 의존성이 없음을 확인했다.

### 화면과 지원 한계

조정자가 실제 PNG를 열어 비율 봉제의 native 표면과 주름, 독립 마네킹, 활성 핀 표시, 해제 후 native 정점 이동을 확인했다. 바디 핀과 일부 봉제 캡처는 천의 검사선이 주로 보인다. `Equal100-10s-surface.png`는 면을 표시하지 못한 반면 `Ratio100_150-10s-surface.png`는 실제 면을 표시한다. 렌더 proxy/LOD/재질/변형 bounds 존재만으로 표면 표시 성공을 판단하지 않는다.

동기 자동화의 PSO 완료 대기와 proxy 확인을 공통 지원에 넣었지만 이 표시 한계를 해결하지는 못했다. 엔진 내장 CPU skinning 진단(`20261017-030710-380`, 재열기 12/12·해시 27개 유지)도 해결하지 못해 해당 override는 최종 코드에서 제거했다. UI/일반 렌더러 개발로 범위를 확대하지 않았다. 최종 코드는 native component와 native 정점 검사선을 사용하며 대체 천 메시를 만들어 결과를 꾸미지 않는다.

100/150cm 케이스는 10초 뒤에도 마지막 1초 최대 0.435583cm/step 진동이 남는다. 설정한 안정성 문턱은 통과했지만 완전 수렴·범용 이즈/주름 품질을 보장하지 않는다. 강제 핀은 자연스러운 피팅이 아니며 골격 포즈 추종, 전체 마네킹 충돌, 면/자가 관통, substep CCD는 검증 범위 밖이다.

## 화면 확인

최종 `Reopen/`의 `free-initial.png` / `free-10s.png` / `free-reset.png`에서 두 패널의 평평한 배치 → 고정점 아래로 매달림 → 원래 배치 복원을 확인했다. 이 무충돌 캡처는 네이티브 정점의 검사선이 주로 보이며 표면 재질 표시 품질을 검증한 결과로 보지 않는다.

`sphere-initial.png` / `sphere-10s.png` / `sphere-reset.png`에서는 실제 Cloth Component 표면과 검사선을 함께 확인했다. `sphere-10s-back.png`에서는 구가 있는 위치에서 천이 휘어지는 모양을 확인했다. 청록/주황은 각 패널, 노랑은 봉제선, 초록은 고정점, 분홍은 구 검사선이다. 정점 선 오버레이를 실제 의상 품질 검증으로 해석하지 않는다.

이미지와 JSON/로그는 전용 `Saved/`에 보존하며 생성물이므로 커밋하지 않는다. 원본 `.uasset` 세 개는 커밋한다. 정확한 생성 경로와 재현 방법은 [REPRODUCTION.md](REPRODUCTION.md)에 있다.

## 실행 중 발견·수정한 문제

- 샌드박스 안에서 엔진 배치 경로 검사가 실패했다. 승인된 외부 실행으로 빌드를 수행했다. 설치 엔진 파일은 수정하지 않았다.
- 최초 타깃의 V6 빌드 설정이 설치 5.8.3의 V7과 불일치했다. 전용 타깃을 V7으로 수정했다.
- 최초 테스트 fixture가 같은 TArray 요소 참조를 다시 Add해 assert했다. 값 복사로 수정 후 두 테스트가 각각 유효 입력 미구현과 네이티브 실험 미구현 때문에 실패하는 RED를 확인했다 (`Saved/Probe/Red/index.json`: 0 성공/2 실패). 이후 실제 구현으로 통과했다.
- 두 번째 Create에서 이미 존재하는 패키지를 완전히 로드하지 않아 저장이 거부됐다 (`Runs/20261017-021331-638/Create-Report`: 1 성공/1 실패). `FullyLoad` 후 객체를 재사용하도록 수정했다. 이어 비동기 PostLoad가 끝나기 전에 Build가 재질 배열을 재설정하는 경고가 있어, 기존 패키지 로드 뒤 asset compilation 완료를 기다리도록 했다. 최종 전체 실행에서 경고 없이 통과했다.
- Cloth 표면 표시 검사 추가 때 protected override 직접 호출로 생긴 컴파일 오류는 공개 SceneComponent 인터페이스 호출로 수정했다. 최종 빌드와 두 프로세스 검증은 모두 통과했다.
- 호스트 시작 시 불필요한 기본 플러그인이 설정을 자동 작성했다. AndroidFileServer/EnhancedInput을 전용 프로젝트에서 비활성화하고, 여전히 엔진이 자동 기록하는 DefaultInput.ini만 호스트 내부 제외 규칙에 넣었다. 공유 `.gitignore`나 메인 설정은 수정하지 않았다.

## 검토와 경계 판단

`requesting-code-review` 절차의 별도 Astra/xhigh 읽기 전용 검토 결과 Critical 0 / Important 0 / Minor 0. 설치 엔진의 실제 seam 용접/solver 경로, 실측 검증, 원본 보존, 경로 격리를 검토했다. 이후 발견한 비동기 PostLoad 경고와 표시 검사 변경은 최종 빌드/전체 자동화로 검증했다. 검토자는 빌드/화면을 대신 확인하지 않았으며 위 실행/화면 확인은 구현 담당이 직접 수행했다.

적용 판단: 사용자가 지정한 현재 checkout과 세 전용 폴더에서 실행했다. 별도 worktree/브랜치나 공용 진행 파일을 만들지 않았다. 추가 착수 승인 없이 승인된 실험만 마쳤다. 현재 checkout을 공유하는 위험은 전용 수정 경로, `-WaitMutex`, 커밋 직전 index 재확인과 명시적 경로 제한 커밋으로 통제한다.

검토에서 판단하지 않은 빌드/최종 화면은 직접 확인했다. 범용 의상 품질·면 관통·substep CCD·제품 통합·배포는 승인 범위 밖이므로 미검증으로 남긴다. 그 비용은 이 결과만으로 실제 의상 제품을 합격 처리할 수 없다는 것이다. 후속 범위로 자동 진행하지 않는다.

수정 범위는 `PluginDev/GarmentFitClothProbeHost/`, `Tools/GarmentFitClothProbe/`, `Docs/Implementation/GarmentFitClothProbe/`뿐이다. 실제 캐릭터, 메인 레벨/WBP, 루트 게임 코드/설정, 기존 LaceGarment, 공유 요청/계획은 수정하지 않았다. 진행 중인 다른 대화의 변경과 커밋은 보존한다.
