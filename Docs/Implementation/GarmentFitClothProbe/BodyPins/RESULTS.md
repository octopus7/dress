## 저장 상태·회귀 검증

핀 생성, 활성/비활성, 해제, 초기화를 API와 실제 native 상태 전환에서 검사했다. `DA_Pins`, `DA_Disabled`, `DA_Released`를 독립 패키지로 저장하고 새 프로세스에서 연다. 세 문서의 바디·변환·출처와 모든 핀 대상 필드/활성 상태/저작 초기화 기준을 비교하고, 현재 상태와 초기화 상태를 실제 용접 정점/바디 목표로 다시 해석한다. 핀 애셋의 정점 위치와 0 가중치 선택, 자유 애셋의 양수 가중치를 해당 문서와 대조한다.

테스트는 정상 입력 외에 잘못된 천 정점, 몸 삼각형, 비유한 목표, 삼각형 바깥 barycentric 값, 표면 안쪽 목표, 활성 충돌 프록시 안쪽 목표, 누락 바디, 용접 별칭 중복/상충 핀, 비단위·0·음수 스케일 등을 거부한다.

RED 증거도 남겼다.

1. `Saved/Probe/REQ026-Red/Report/index.json`: 기능 스텁에서 BodyPins 계약/네이티브 두 테스트가 의도대로 실패했다.
2. `Saved/Probe/REQ026-LifecycleRed/Report/index.json`: 해제 후 같은 ID 재저작에서 이전 저작 기록이 중복되는 문제를 재현했다. 이후 `CreatePin`의 최신 유효 저작 스냅샷 저장으로 수정했다.
3. `Saved/Probe/Runs/20261017-030029-480/Create-Report/index.json`: 해제 문서의 초기화 삼각형/오프셋, 비활성 문서의 천 정점/바디 변환을 손상시킨 4개 회귀가 기존 개수 검사에서 실패했다. 보강된 검사로 최신 전체 생성·재열기에서 통과했다.

## 남는 한계와 화면

**해제와 비활성은 연속적인 물리 전환이 아니다.** 네이티브 질량 설정을 다시 만들기 위해 자유 애셋/프록시로 교체하며, 초기 배치와 속도가 재설정된다. 위 표의 점프 수치가 이 불연속을 드러낸다. 해제 뒤에는 실제 자유 시뮬레이션이 복구되지만 기존 속도를 보존한다고 주장하지 않는다.

지원하는 바디 추종은 고정 바인드 포즈 메시의 강체 이동·회전이다. 골격 애니메이션 또는 자세 변형 추종은 구현/검증하지 않았다. 강제 핀 결과를 자연스러운 의상 피팅 성공으로 해석하지 않는다.

구 프록시는 각 표면 목표 근처의 반지름 4cm 구일 뿐 전체 마네킹 충돌체가 아니다. 겹침 값 0은 매 1/60초 정점 샘플에서 겹침을 관찰하지 못했다는 뜻이다. 이 기능의 별도 무프록시 접촉 대조군은 없으므로 접촉 반응의 인과적 입증, 전체 몸/천 면의 비관통, substep CCD로 확대하지 않는다. 기존 최소 probe의 구 충돌 대조군 검증은 별도로 유지된다.

`Reopen/BodyPins/body-{initial,follow,disabled,released,reset,no-pin}.png`와 `Reopen/Integration/combined-*.png`에서 실제 독립 마네킹과 핀 상태 및 native 측정 천 와이어를 확인했다. 녹색은 활성 핀, 빨간 목표 원/주황 정점은 비활성·해제 상태다. **천의 채워진 표면은 현재 캡처에서 충분히 보이지 않아 와이어 중심이다.** 실제 native render proxy의 존재와 PSO 완료를 검사해도 같은 현상이 남았다. 면 렌더링을 해결했다고 보고하지 않으며 별도 대체 천 메시를 만들어 결과를 가장하지 않았다.

최초 FBX 임포트 런 `20261017-025255-243`에는 MikkTSpace의 degenerate tangent/nearly-zero binormal 경고가 있었다. 텍스처가 없는 사본의 임포트 노멀은 보존하고 BuiltIn tangent 방식으로 기존 사본을 재빌드한 뒤 최신 생성/재열기는 경고 없이 통과했다. 새 BuiltIn 임포트 옵션을 빈 패키지에서 처음 임포트하는 경로는 최신 런에서 별도로 재실행하지 않았다. 고정 원본과 추출 해시는 [SNAPSHOT.md](SNAPSHOT.md)에 있다.

제품 통합, 새 편집 UI, 골격 포즈 추종, 연속 release, 배포·cook은 이 검증으로 완료 처리하지 않는다. 기능별 Git 커밋은 조정자가 공용 변경과 함께 별도 기록한다.
