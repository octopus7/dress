# REQ-026 BodyPins 구현과 검증 범위

상태: Editor 빌드와 전체 자동화 Create 12개 / 새 프로세스 Reopen 12개가 경고 없이 통과했다. 구체적 실측, 원본 보존과 와이어 중심 캡처 한계는 [RESULTS.md](RESULTS.md)에 기록했다. 빌드·UE 실행·최종 커밋은 조정자만 수행한다.

## 데이터와 API

`Private/BodyPins/BodyPinProbe.h`의 `UGarmentProbeBodyPinSet`은 독립 마네킹 메시 경로, 강체 바디 변환, 현재 핀 목록, 초기화용 저작 핀 목록과 고정 사본 출처를 직렬화한다. 각 핀은 이름, 패널 로컬 2D 정점, 마네킹 렌더 삼각형 인덱스, barycentric 좌표, 표면 오프셋(cm), 활성 상태를 가진다.

`CreatePin`, `SetPinEnabled`, `ReleasePin`, `ResetPins`가 문서 상태를 변경한다. 핀 생성에 성공하면 현재 유효 핀 목록을 최신 저작 초기화 기준으로 저장하므로, 해제 후 같은 ID를 다시 저작해도 예전 핀이 중복 복구되지 않는다. `ResolvePins`는 패널 로컬 정점을 공통 `Support::ResolveVertex`를 통해 실제 용접 3D 정점으로 바꾸며, 동일 용접 입자의 중복·상충 핀은 비활성 상태를 포함해 거부한다. 등록 실패는 현재 목록과 초기 목록에 부분 변경을 남기지 않는다. `WorldTarget`은 바디 로컬 목표를 강체 월드 변환으로 계산한다.

`BuildPinAsset`은 바디 로컬 초기 배치가 명시된 입력 Cloth Asset의 Collection을 복사한다. 활성 핀 정점의 사본 초기 위치를 실제 표면 목표로 저작하고, 해당 정점의 `MaxDistance`를 0으로 지정한다. 나머지는 2000cm다. 원본 입력을 변경하거나 저장하지 않는다. 2D 원본 재단 좌표는 유지한다. 비교용 자유 애셋은 핀 배치가 끝난 사본에서 생성하므로 양쪽의 최초 3D 배치도 같다.

## 네이티브 동작 경로

1. `FClothGeometryTools::BindMeshToRootBone`이 실험 사본을 기본 Root에 바인딩한다.
2. 설치 엔진 `ChaosClothingSimulationCloth.cpp`의 `FLODData::Initialize`는 `MaxDistance < 0.1`인 입자를 kinematic으로 분류하여 native solver 입자의 역질량을 0으로 만든다. 실험에서는 정확히 0을 사용한다.
3. `UChaosClothComponent`의 바디 로컬 초기 배치와 루트 skinning 목표가 컴포넌트의 월드 변환으로 변환된다. 매 스텝 보이는 마네킹과 Cloth Component에 같은 강체 변환을 전달하므로 kinematic 입자가 몸을 따른다.
4. 위치 측정은 `FClothSimulationProxy`의 native simulation output에서 읽는다. 시뮬레이션 뒤 정점 위치를 덮어쓰거나 별도 솔버를 사용하지 않는다.

입자 질량 분류는 생성 단계에서 이루어지므로 이 실험의 활성/비활성/해제 전환은 준비된 네이티브 핀/자유 애셋으로 교체하여 프록시를 재생성한다. **이 전환은 위치와 속도를 초기화한다. 연속적인 release는 지원한다고 주장하지 않는다.** 측정 파일의 `reset_discontinuity_max_cm`에 실제 점프를 기록하고, 이후 이전 핀 정점 모두가 중력으로 5cm 이상 이동·하강하는지 검사한다. 초기화는 저작 핀 상태와 배치를 복구한다.

## 마네킹과 표면/충돌 정책

고정 FBX 출처는 [SNAPSHOT.md](SNAPSHOT.md)에 기록했다. UE FBX 임포터로 모든 메시를 하나의 독립 정적 바인드 포즈 마네킹으로 임포트하며, 고유 경로의 무광 재질을 적용한다. 다른 프로젝트의 `/Game/` 애셋 참조는 필요하지 않다.

목표는 실제 마네킹 LOD0 렌더 삼각형의 barycentric 점이다. 삼각형 기하 법선의 방향은 임포트된 렌더 정점 법선으로 정한다. fixture는 마네킹 높이의 약 72%에서 +Y 방향을 향하는 표면을 선택하고, 1.5cm 바깥쪽으로 띄운다. 기록된 삼각형 인덱스와 오프셋으로 목표를 재계산한다. 골격 포즈 변형은 이번 지원 범위가 아니다.

각 핀 표면 근처에 반지름 4cm의 네이티브 구 프록시를 배치하고, 시뮬레이션 정점과의 겹침을 샘플링한다. 이는 마네킹의 전체 충돌체가 아니다. **겹침 측정값 0은 이 BodyPins 실험에서 접촉 반응을 인과적으로 입증했다는 뜻이 아니다.** 별도 무프록시 접촉 대조군은 추가하지 않았으며, 기존 최소 probe의 구 충돌 대조군 검증과 구분한다. 음수/1cm 미만 표면 오프셋, 잘못된 삼각형과 barycentric 값, 비유한 값, 활성 프록시 내부 또는 1cm clearance를 침범한 목표를 거부한다. 비단위 스케일은 모두 거부한다. 이 정책은 전체 마네킹 내부/외부 판정이나 몸 전체의 비관통을 보장하지 않는다.

## 실행과 결과 파일

조정자 공용 runner의 `-Suite BodyPins`는 `TargetAndLifecycle`, `NativeFollowReleaseAndReopen`을 실행한다. `-Suite Integration`은 봉제 에이전트의 읽기 전용 입력을 자기 폴더에 복사해 봉제와 핀을 함께 실행한다. 이때 첫 봉제 대응의 두 2D 별칭이 같은 용접 입자이고, 핀이 해당 입자를 가리키는지 검사한다. 사본 배치는 회전·이동만 하며 원본 2D 길이를 변경하지 않는다.

BodyPins 결과는 `body-`, 통합 결과는 `combined-` 접두사를 사용한다.

| 파일 접미사 | 확인할 내용 |
| --- | --- |
| `follow-metrics.json` | 120프레임 정지 + 120프레임 이동/45도 회전, 최대 핀 목표 오차, 목표 월드 이동, 프록시 정점 관통, 실제 native 입자 수 |
| `disabled-metrics.json` | 비활성 후 실제 이전 핀 정점의 이동·하강, 역질량0 입자가 사라짐, 초기화 점프 |
| `released-metrics.json` | 핀 해제 후 같은 자유 시뮬레이션 검사 |
| `reset-metrics.json` | 저작 상태·배치 복구 오차 |
| `no-pin-metrics.json` | 동일 최초 배치와 정지 바디의 핀 없는 대조군 |
| `summary.json` | 마네킹/원본 blob, 패널 정점→용접 정점, 삼각형 목표, 지원 범위와 한계 |

모든 `*-metrics.json`에 `final_positions`를 둬 생성 프로세스와 새 프로세스 재열기의 결과를 비교한다. `DA_Pins`, `DA_Disabled`, `DA_Released` 세 문서의 현재/저작 상태를 실제 패키지로 저장하고 재열기에서 검증한다. 저장 상태 검사는 개수만 확인하지 않는다. 바디/변환/출처, 핀 ID, 패널 정점, 삼각형, barycentric 좌표, 오프셋, 활성 상태와 초기화 기준을 비교하고, 세 문서의 현재 상태와 초기화 결과를 다시 용접 정점/목표로 해석한다. 실제 핀 애셋의 목표 위치와 MaxDistance=0 선택, 자유 애셋의 양수 맵을 문서에 대조한다. 실행 중의 각 상태 전환에서도 이 대조를 수행한다. 재열기 모드는 원본 애셋을 저장하지 않는다.

PNG는 실제 마네킹과 native Cloth Component가 있는 preview scene을 캡처한다. 선은 측정된 천 토폴로지의 보조 표시다. 녹색은 활성 목표/핀, 빨간 원은 비활성 또는 해제 목표, 주황 점은 이전 핀 입자의 현재 위치, 노란 선은 표면 방향이다. 강제 부착을 자연스러운 피팅 성공으로 해석하지 않는다. 캡처에서는 마네킹/핀/천 와이어를 확인했으며 천 면이 표시되지 않는 한계가 남아 있다. PSO 완료와 실제 native render proxy 존재 검사를 추가해도 같은 현상이 관찰됐으므로, 해당 검사만으로 면 렌더링을 해결했다고 판단하지 않는다.

관통 수치는 매 1/60초 시뮬레이션 정점과 구 프록시의 거리 샘플이다. 삼각형 면 관통, 전체 마네킹 관통, substep CCD 또는 범용 의상 품질 검증은 아니다.
